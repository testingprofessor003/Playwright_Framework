High Level Design (HLD)

Playwright BDD Cucumber Framework · Version 1.2 · TypeScript

1. Purpose

This framework is a reusable UI automation platform using Playwright and Cucumber BDD. It standardizes Gherkin features, thin step definitions, business classes, page objects, actions, wait/assertion utilities, logging, error classification, env-driven artifacts (step screenshots, video, traces), Extent-style activity reporting, CI/CD, BrowserStack, database-backed history, and local LLM failure triage with complexity-based model routing.

The current application under test is the core banking site at https://corebanking.testingprofessor.net/.

2. Goals

  • BDD-first authoring with Gherkin features and thin step definitions that call business classes.
  • Page Object Model with a single action utility wrapping Playwright APIs.
  • Deterministic error taxonomy wrapping Playwright exceptions.
  • Worker-safe shared data for parallel and cross-browser runs.
  • Allure, custom failure HTML, Extent activity report, and historical dashboard.
  • Env-driven per-step screenshots, scenario screenshots, video, and Playwright traces.
  • Optional MySQL or PostgreSQL persistence.
  • GitHub Actions, Jenkins, Docker, and BrowserStack integration.
  • Hosted Ollama LLM triage: llama3 routes work; complex analysis prefers ~32B models, then gemma4:latest.

8. LLM triage and model routing

The hosted Ollama server is http://localaiserver.testingprofessor.net. Calls use LLM_API_KEY. Catalog comes from GET /api/tags (including details.parameter_size).

flowchart TB Fail[Failed scenario] --> Tags["GET /api/tags catalog + parameter_size"] Tags --> Est[Estimate complexity] Est --> Llama["llama3 router 8B or less"] Llama -->|simple| Small["llama3* small"] Llama -->|medium| Mid["~8B llama3.1 or similar"] Llama -->|complex| Big["~32B class then gemma4:latest"] Small --> Chat["POST /api/chat JSON insight"] Mid --> Chat Big --> Chat Chat --> Store[history + DB ai_insights] Store --> UI[Extent / custom HTML / dashboard]
ComplexityPreferred model
Simple (short timeout / locator miss)Small llama3* (8B or less), never a 32B model
Medium~8B class unless the failure looks ambiguous
Complex (long stack, PW_UNKNOWN)~32B installed model (27B–40B band), else gemma4:latest, else larger

LLM_MODEL=auto and LLM_ROUTE=true enable routing. LLM_PREFER_BILLION=32 sets the complex-size target. LLM_COMPLEX_MODEL=gemma4:latest is the named fallback.

9. Deployment views

9.1 Local

Node 24 LTS+, Playwright browsers, optional MySQL/Postgres. Dashboard on port 3000. LLM defaults to the hosted server localaiserver.testingprofessor.net (not a local Ollama process).

9.2 Docker Compose

Services: mysql, postgres, ollama (optional local), dashboard, tests (profile). Tests write reports to a bind-mounted volume. Hosted LLM can replace compose Ollama via LLM_HOST.

9.3 Cloud

When EXECUTION_ENV=browserstack, the runner connects via Playwright CDP WebSocket using BrowserStack capabilities instead of launching a local browser.

10. Data sharing

Cucumber workers do not share Node memory. SharedBuffer exposes three scopes:

  • scenario — in-memory Map on World (isolated).
  • worker — in-memory Map per worker process.
  • global — locked JSON file plus optional shared_kv table so Chrome/Firefox/WebKit and CI shards can exchange keys.

Customer flows persist customer, customers, accounts in scenario and global scopes so later steps (open account, customer login) can reuse generated data.

12. Non-functional requirements

  • Isolation: new browser context per scenario.
  • Parallel: Cucumber --parallel with file-locked global store; AfterAll triage runs on the primary worker only.
  • Resilience: DB and LLM are optional; JSON history and Extent still generate.
  • Security: credentials and LLM_API_KEY only via environment / CI secrets, never committed.
  • Extensibility: add a page class + business method + feature + thin step without changing core.

13. Constraints and assumptions

  • TypeScript 7 on Node 24 LTS or later, executed with tsx (not ts-node).
  • Playwright 1.62.1 library (Cucumber is the test runner; Playwright Test is not used as the runner).
  • Core banking pages are implemented; templates/ExamplePage remains a scaffold for new pages.
  • The local AI server requires a valid LLM_API_KEY. HTTPS to that host is not used; HTTP is.
  • 32B-class models are detected from Ollama catalog metadata or names such as :32b.
