2. Configuration contract

Loaded from .env via src/config/env.ts.

AreaKeys
AppBASE_URL, APP_USERNAME, APP_PASSWORD, APP_ENCRYPTION_KEY
BrowserBROWSER, BROWSER_CHANNEL, HEADLESS, KEEP_BROWSER_OPEN, SLOW_MO, PARALLEL, LOGIN_PAUSE_MS, CLICK_PAUSE_MS
ArtifactsSCREENSHOT, STEP_SCREENSHOT, SCREENSHOT_FULL_PAGE, VIDEO, TRACE — each off | on | retain-on-failure
Self-healSELF_HEAL_ENABLED (alias SELF_HEAL), SELF_HEAL_USE_LLM, SELF_HEAL_TIMEOUT_MS
LLMLLM_ENABLED is the on/off switch. OLLAMA_ENABLED is the same flag (alias), not a second setting. Host/model/key: LLM_HOST, LLM_API, LLM_API_KEY, LLM_MODEL, plus LLM_ROUTE, LLM_ROUTER_MODEL, LLM_COMPLEX_MODEL, LLM_PREFER_BILLION, LLM_TIMEOUT_MS. OLLAMA_HOST / OLLAMA_MODEL / OLLAMA_API_KEY alias the matching LLM_* names.
OtherEXECUTION_ENV, DB_*, BROWSERSTACK_*, LOG_LEVEL

Paths of note: reports/downloads/ (saved files), reports/self-heal/healed-locators.json (heal cache), recordings/test-runs/ (videos).

Run identity: RUN_ID env or file-locked reports/.run-id so all workers share one run.

Defaults: LLM_HOST=http://localaiserver.testingprofessor.net, LLM_API=ollama, LLM_MODEL=auto, LLM_ROUTER_MODEL=llama3, LLM_COMPLEX_MODEL=gemma4:latest, LLM_PREFER_BILLION=32, SELF_HEAL_ENABLED=false, CLICK_PAUSE_MS=800.

HookBehavior

BeforeNew context/page, optional video dir and tracing, init SharedBuffer scenario scope, start Extent scenario

5.1 Self-heal

flowchart TD Act[runWithHeal action] --> Try[Original locator] Try -->|pass| Done[Return] Try -->|ELEMENT or TIMEOUT| Flag{SELF_HEAL_ENABLED?} Flag -->|no| Fail[Rethrow FrameworkError] Flag -->|yes| Cache[healed-locators.json] Cache -->|hit| Retry1[Retry healed] Cache -->|miss| Heur[role / text / placeholder / label / css] Heur -->|ok| Store[Remember + retry] Heur -->|miss| Llm{SELF_HEAL_USE_LLM?} Llm -->|yes| Suggest[LLM locator suggestion] Suggest --> Store Llm -->|no| Fail Retry1 --> Done Store --> Done

Successful heals are logged as Extent selfHeal activities. Prefer fixing page-object locators; treat heal as a resilience layer, not the primary design.

9. Database ER

erDiagram test_runs ||--o{ test_scenarios : contains test_scenarios ||--o{ test_steps : contains test_scenarios ||--o{ failures : has test_runs ||--o{ ai_insights : has shared_kv ||--|| shared_kv : kv test_runs { string id PK string started_at int passed int failed string status } test_scenarios { string id PK string run_id FK string status int duration_ms string screenshot_path string video_path string trace_path } failures { string id PK string error_code string error_category } ai_insights { string id PK string likely_cause string suggested_fix string category string confidence }

Placeholders use ?; the Postgres client rewrites them to $1..$n. Upsert for shared_kv uses REPLACE INTO (MySQL) or ON CONFLICT (Postgres).

If DB_ENABLED=false, repository methods no-op and the dashboard reads reports/history/*.json. History insights may include model (chosen LLM) even if the DB column is not present.

12. LLM triage and routing

Modules:

  • llmClient.ts — Ollama /api/tags and /api/chat (OpenAI /v1/* fallback), Bearer + X-API-Key, timeout, catalog with parameterBillion.
  • modelRouter.ts — estimate complexity; list catalog; ask small llama3 to pick; heuristic if router missing.
  • FailureTriage.ts — JSON prompt for likelyCause / category / suggestedFix / confidence; stores model.
  • runTriage.ts — iterate history failures, skip already-triaged, write custom report.
  • llmHealth.ts — npm run ai:health prints installed models and 32B-class entries.
sequenceDiagram participant T as runTriage participant R as modelRouter participant O as Ollama API participant F as FailureTriage T->>O: GET /api/tags O-->>R: names + details.parameter_size R->>R: estimateComplexity R->>O: POST /api/chat llama3 JSON route O-->>R: model + complexity alt complex R-->>F: ~32B or gemma4:latest else simple R-->>F: small llama3* end F->>O: POST /api/chat chosen model O-->>F: JSON insight F-->>T: persist insight + model name

32B-class band is 27B–40B so names like qwen2.5:32b, llama3.1:32b, and gemma2:27b qualify. Size is taken from details.parameter_size or parsed from the tag (:32b, 8x7b MoE). The llama3 router itself is constrained to models ≤ 8B so a 32B llama3 is not used for routing.

Heuristic when llama3 is not installed: complex → closest ~32B then gemma4:latest; simple → smallest llama3*; medium → ~8B.

Auth: nginx in front of the server returns 401 without LLM_API_KEY. Chat is skipped with a warning; reports still generate.

13. BrowserStack connect

wss://cdp.browserstack.com/playwright?caps=<urlencoded JSON>

Caps include browser, os, build, username, accessKey, scenario name. Local launch path is skipped when EXECUTION_ENV=browserstack; each scenario connects and closes its own remote browser.

14. CI/CD

  • GitHub Actions: matrix chromium/firefox/webkit against https://corebanking.testingprofessor.net/; required secrets APP_USERNAME / APP_PASSWORD (optional APP_ENCRYPTION_KEY); LLM_ENABLED=false; tags @smoke and not @example; artifact upload; optional BrowserStack job.
  • Jenkins: install, optional migrate, test, Allure + HTML publisher.
  • Docker: official Playwright image; compose brings MySQL, Postgres, Ollama, dashboard, tests profile. Hosted LLM is selected with LLM_HOST / LLM_API_KEY.

16. Logging format

Console: timestamp, level, runId|workerId|scenarioId, message. Files: JSON in logs/framework.log and logs/errors.log with rotation. Step screenshots, self-heal retries, and LLM route decisions are logged at info.
